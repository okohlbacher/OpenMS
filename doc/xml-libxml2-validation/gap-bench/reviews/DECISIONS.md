## Final Kimi counterexamples checked against code and execution

Kimi's second pass reported two defects that are not reproduced by the supplied code/evidence:

1. **XML pruning:** `e.clear()` and parent removal are inside the spectrum-end branch; only `stack.pop()` is unconditional. Thus scan/precursor descendants are available when the spectrum is audited. The real metadata receipt and final inflater gates were produced successfully, and the timed matrix starts after their markers. The source packet preserves indentation; no unconditional-pruning change was applied.
2. **RSS-floor premise:** the actual raised-parent control records C++ VmHWM39,436,288 bytes, native-child wait4 peak39,845,888 and outer Python wait4 peak154,140,672. The native meters agree while the outer floor persists; all strict control assertions pass on Linux6.8.0-124. `exec` resets the new mm's VmHWM, but Linux also saves the old mm high water in `signal->maxrss` ([Linux6.8 exec_mmap](https://github.com/torvalds/linux/blob/v6.8/fs/exec.c#L990)). Treating wait4 as only the new mm's hiwater is incorrect. The native supervisor's tiny launch floor is separately calibrated at1MiB and disclosed. The suggested equal-outer-RSS assertion would contradict this host's measured control, so it was not applied.

The original plan required450 cells×5 repetitions. The later explicit user-requested reduction below supersedes that count; identity, fingerprints and complete post-validation remain mandatory. Superseded pilots and expected-negative controls are reported separately.
