## Schedule and clocks

Three fresh processes per cell at 1/32/64/96 independent readers. The initial all-reader experiment had264 processes (88 cells) and 54 longer confirmations. It is preserved as a rejected candidate because IM query loops slowed. Separate direct-fragment-copy and packed-ID experiments also remain excluded. No fastest-repetition selection or pooling of rejected versions is permitted.

The final primary matrix runs 132 new candidate processes and reuses the 132 unchanged original baseline processes. Roles have identical primary CPU masks. It covers context retention, synchronized indexed reads and matching idle at every N. A separate 60-process paired sustained matrix reruns the original nine flagged input/N cases plus IM at 1 reader. The final selected data therefore contain 324 workload records/108 three-repetition cells, with 192 new processes. Fifteen untimed preflight/control processes are separate. An early final-wrapper CPU-mask mismatch was stopped; its entire pilot remains excluded with an operator receipt. It is not a successful measurement or part of the selected counts.

Primary indexed loops issue256 queries per reader (IM 64); sustained loops issue8192 (IM 2048). Query sequence is deterministic. Returned spectrum counts, points, ordered index fingerprints and data digests must agree. A full mincore gate verifies every input page resident before each timed process. Native exit status, actual library, affinity, emitted worker count and complete schedule are checked; source/input/runtime identities are rehashed after the matrix.

Three clocks have distinct meanings:

- Whole workload includes open, reads, destruction and joins.
- Global synchronized read phase starts after every reader has opened, and includes destruction/join.
- Per-worker query loop excludes open, the start barrier and destruction. Each process contributes the median worker loop; the table then summarizes the three process medians.

A >5% median slowdown triggers investigation; it is a descriptive threshold, not a statistical significance test. Short loops cannot establish equivalence. Larger speed claims must survive the sustained phase. All timings and ranges remain visible, including slower teardown.

## RSS and allocator evidence

C++ `/proc/self/status` VmHWM is authoritative for native process peak RSS. A native fork/wait4 supervisor and sampled child VmHWM are cross-checks; the Python parent's inherited peak is not substituted for the native process value. Post-join `/proc/self/statm` is a separate resident sample. Context objects remain alive after workers join only in `contexts` mode. The per-reader estimate subtracts same-N idle RSS and divides by N; it includes offset maps, strings and allocator state, not isolated `sizeof(xmlParserCtxt)` or live thread stacks. Indexed post-join RSS is residue after readers are destroyed.

Separate untimed `mallinfo2`/statm probes distinguish live allocations from free arena memory and trace before/retained/closed states. Probes with `malloc_trim(0)` are labeled diagnostic; no-trim traces remain visible. The all-reader implementation can leave more pages after cross-thread destruction despite lower active-context RSS; no guarantee is made that object destruction returns every page to the OS. Fixed malloc environment experiments are diagnostic and excluded; fixing those settings disables glibc's normal dynamic heuristics and is not a product solution.
