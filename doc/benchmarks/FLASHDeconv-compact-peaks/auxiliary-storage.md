# Auxiliary storage alternatives

The 32-byte `LogMzPeak` facade keeps three independent doubles (`mz`, `log_mz`, `mass`), a float intensity, and two 16-bit words. Its scalar storage and defaulted copy/destruction need no external owner, pool, or lookup when peaks are copied, assigned, sorted, or destroyed. The measured 48-to-32-byte layout change is an object-size result; native RSS and elapsed results belong to the separate compact experiment.

Neither m/z nor cached logarithm can simply be reconstructed from the other while preserving the current API. `setMZ` and `setLogMz` deliberately operate independently, and recomputing with `exp` or `log` can change floating-point results. Mass is also an independent value: `getMass` returns the stored double, whereas `getUnchargedMass` returns zero for charge zero, derives mass for a nonpositive stored value, and otherwise returns the override. A NaN override takes the latter branch because `NaN <= 0` is false. The ordinary scientific call sites reviewed here do not write mass overrides, but public C++ and Python clients and existing tests do. That lexical observation does not justify deleting the value contract.

| Choice | Potential benefit | Required ownership and cost |
|---|---|---|
| Inline 32-byte value | Compact contiguous peaks; independent values and cheap copies | Keeps all three doubles; no auxiliary ownership or synchronization |
| 24-byte value plus rare mass sidecar keyed by object address | Removes one double from every peak; only nondefault mass overrides need sidecar entries | Requires custom copy/move/assignment/destruction, address rekeying, exceptional allocation handling, and synchronized shared metadata |
| Spectrum-owned m/z/mass arrays | One immutable original payload can serve many internal references | Every reference needs a stable owner plus identity; cannot outlive or mutate the input independently without materialization; an 8-byte pointer can erase the proposed 8-byte saving |
| Private structure-of-arrays or indexed peak view | Can separate hot fields from rarely consumed payload and reduce private copies | Requires an explicit spectrum/run owner and conversion at public value boundaries; indexes, sorted order and copied results must remain valid |

The 24-byte arithmetic is 8 bytes saved per live/reserved slot, or 25% of the 32-byte payload. For capacity `C` and `K` override entries, the net storage change is `8*C` minus the sidecar's entries, buckets, allocator overhead and synchronization state. Neither `K` nor that overhead has been measured. A 24-byte stride fits eight records in 192 bytes rather than six 32-byte records; individual records can cross a 64-byte line. These are layout facts, not measured cache or RSS gains.

An address-keyed sidecar must preserve an object's value rather than associate metadata permanently with a memory slot. Vector growth, element insertion/erase, `std::sort`, `std::swap`, assignments, and temporaries change which value occupies each address. The peak sorting and copying paths are real callers, not an edge-only concern. Every custom operation must transfer or duplicate an override, erase the old destination override, handle self-assignment and self-move, and leave moved-from objects destructible. Missed cleanup can leak entries or let a later object at the same address inherit stale mass. Binary relocation of a formerly trivial value would cease to be correct.

A per-thread map is insufficient: peaks can be copied into results and destroyed or read by another thread. A process-wide map needs safe concurrent lookup/mutation, including rehash, and process-exit lifetime independent of all peak destructors. A mutex or sharded map avoids a single unsynchronized container but does not establish low contention. Rare overrides can avoid common-path lookups with a flag; they cannot eliminate lifecycle branches on every value operation. Copying an overridden peak needs storage for a second entry. This conflicts with today's allocation-free `setMass(double) noexcept` and trivial scalar copying unless the experiment explicitly changes exceptional behavior. A flag only for positive values is also insufficient: `getMass` must preserve negative values, negative zero, infinities and NaNs. A default-elision policy must compare the chosen default's representation, not discard all nonpositive values.

The smallest safe next step is to retain the 32-byte facade until its native results are complete. If more compaction is justified, prefer an explicitly private, owner-scoped hot representation with public values materialized at clear boundaries. A rare sidecar is feasible only as a separately reviewed API/value-type change, with measured override frequency and full copy/move/sort/concurrency/failure tests. It is not a one-field removal or a free global array.
