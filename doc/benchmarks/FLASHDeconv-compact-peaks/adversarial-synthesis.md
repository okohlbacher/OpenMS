# Adversarial synthesis: compact inline peaks

The experiment preserves three inline doubles and one float, replacing the old integer/polarity fields with a checked 16-bit flag word and unsigned 16-bit isotope magnitude. It owns every peak directly. The measured Linux ABI stride is 48→32 bytes. This is an explicit C++ source/API and ABI experiment, with charge magnitude 0–200 and signed isotope indices −65535–65535. Python retains the seven writable attribute names; it does not retain unrestricted integer assignments.

The actual external reviews used the same 72,002-byte source packet, SHA-256 `e2238eec598d0abff859960071e3c7ec4aaa28c0c8437039bdd929540bb68e27`. Claude's emitted metadata identifies **Opus 5.5** (`claude-opus-5-5`). The other review ran through **Kimi CLI 2.2.0**; its exact underlying model was not verified. Both completed successfully with no tool calls and unchanged supplied source. Their verdicts concerned an earlier unbuilt draft. See `review-provenance.json` for exact outcome/review hashes.

Both reviewers found real accessor errors introduced by mechanical migration: the storage aggregate was incorrectly called as though it had methods. The tested source uses its actual scalar members. Both also challenged integer narrowing, old public-field consumers and exceptions escaping OpenMP. The final experiment checks charge/isotope ranges before mutation, guards min_charge/max_charge before their absolute-value conversions, and catches candidate, harmonic and FDR-section failures inside their respective regions, rethrowing after joins. The old finite/range assumptions of floating-to-int conversions elsewhere remain explicit. This is a restricted experiment, not proof that arbitrary old inputs still succeed.

A signed 16-bit flag word was retained rather than the proposed unsigned word: the requested representation and all setter states remain within 0..0x3ff, so conversion back to int16 is representable; mask operations preserve charge, polarity and isotope-sign independently. Negative polarity remains possible at charge 0. Negative isotope values beyond −1, both signed bounds and zero-sign reset are preserved. Independent mz/logarithm/mass writes, charge-zero-before-override behavior and original arithmetic precision/order remain. Actual boundary, state-preservation, copy, comparison and hash checks support these source arguments.

The review request for complete consumer closure led to preprocessing all 760 actually linked library recipes and rebuilding the 11 library consumers plus affected client/tests: 22 fresh translation units. Thirteen focused tests and 24 complete small exports passed against the cap64 reference at 1/4 threads, ordinary/FDR. A separate public C++ oracle checked 3,216 packed states and 65,536 normalized value/copy/sort peaks. The whole updated binding source compiled; the exact LogMzPeak binding block passed 12 runtime tests. These are bounded checks, not a full all-target build or a full pyOpenMS wheel/runtime test. Actual identifiers and scope are in `validation-summary.json`.

No global auxiliary table or per-worker backing arena was introduced. Moving mass alone behind a32-bit index keeps a 32-byte aligned stride while adding a lookup and auxiliary storage. Moving mz and mass together could give 24-byte handles, but changes ownership, sharing, mutable copy semantics and lifetime rules. That larger design was deferred. A reordered 40-byte wide-integer control was also not measured, so this experiment cannot separate the effects of packing, reordering and accessor migration.

The 32-byte layout reduces identical peak-vector capacity by one third; it does not imply a one-third RSS or runtime reduction. No hardware cache-miss, bandwidth, IPC or NUMA counters support a cache claim. Complete-file native results are reported through their closed measurement cohort, separately from the diagnostic census and the correctness-only C++ oracle. No timing or RSS point is invented in this evidence bundle.

The final branch differs from immutable tested R2 in only two recorded whitespace changes: namespace indentation and spacing before braced hash construction. The other 16 source files remain byte-identical. Stripped whitespace and line counts match in both changed files; `source-provenance.json` binds both versions. These source-relation checks do not claim that the final whitespace bytes were separately compiled.
